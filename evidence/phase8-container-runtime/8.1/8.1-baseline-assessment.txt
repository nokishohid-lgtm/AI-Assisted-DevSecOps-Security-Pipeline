Baseline Findings
-----------------
1. Runtime base images use mutable tags rather than immutable digest references.
2. Runtime Dockerfiles execute apk upgrade during image construction.
3. PostgreSQL does not currently use the same capability and security_opt hardening as API and worker.
4. PostgreSQL root filesystem remains writable because database persistence requires controlled writable storage.
5. Database credentials are currently defined directly in docker-compose.yml.
6. API, worker, and database currently share a single bridge network.
7. API and worker runtime images can be reviewed for further minimization.
8. Docker build context can be reduced further through .dockerignore improvements.

Important PostgreSQL Observation
--------------------------------
docker compose exec postgres id opened an administrative shell as root.

However, inspection of the actual running database processes with docker top showed the PostgreSQL server and supporting processes running as UID 70.

Therefore, the database server itself is operating as a non-root runtime process.

Conclusion
----------
The Phase 8.1 baseline is operational and already contains several strong runtime controls.

The environment is suitable for continued hardening in Phase 8.2 through Phase 8.8.

Final Result: PASS
